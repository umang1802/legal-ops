# Firm Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Firm owners and admins upload a PNG or JPG logo. It shows in the app (sidebar, mobile header), on invoice, receipt, diary and matter-history printouts, and in client emails, with "Powered by LexForgeX" in the app, on invoices, on receipts and in emails.

**Architecture:**
- **Upload:** the browser PUTs the logo straight to the documents S3 bucket with a signed URL. The API then reads the object back, checks its size and magic bytes, and saves `logo_id`/`logo_type` on `organizations`.
- **Serving:** an unauthenticated route streams `org/<orgId>/branding/<logoId>.<png|jpg>` with immutable caching. Its path is the logo URL used everywhere: `/auth/me`, `GET /organization`, and absolute in emails.

**Tech Stack:** pnpm monorepo. Express 5 API with tagged-template SQL on `pg`. `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` (already installed). Zod. Vitest + supertest on Postgres `legalops_test` (port 5433). React web app with TanStack Query and `@legalops/ui`.

**Spec:** `docs/superpowers/specs/2026-10-30-firm-logo-design.md`

## Global Constraints
- **Allowed files:** PNG (bytes start `89 50 4E 47 0D 0A 1A 0A`) or JPEG (bytes start `FF D8 FF`) only, at most **1 MB = 1,048,576 bytes**. Content types `image/png`, `image/jpeg`. Stored extensions `png`, `jpg`.
- **Object key:** `org/<orgId>/branding/<logoId>.<png|jpg>`. `logoId` is a new random UUID for every upload.
- **Public path:** `/api/v1/public/logos/<orgId>/<logoId>.<png|jpg>`.
- **Public route headers:**
  - `Cache-Control: public, max-age=31536000, immutable`
  - `X-Content-Type-Options: nosniff`
  - `Cross-Origin-Resource-Policy: cross-origin`
- **Signed upload URL** valid for 300 seconds.
- **Permission** `organization.manage`. Suspended firms are blocked by the existing middleware.
- **Audit actions:** `organization.logo_updated` and `organization.logo_removed`.
- **Copy:**
  - footer line `Powered by LexForgeX` (in the app, on invoices, on receipts, in emails; it replaces "Sent via LexForgeX" in emails)
  - errors `That file isn’t a PNG or JPG` and `Logos can be up to 1 MB`
  - settings hint `Shown in the app, on invoices and receipts, and in emails to clients.`
- **Replacing or removing a logo never deletes earlier logo files.** Sent emails keep working.
- **Migration** `packages/db/migrations/0015_organization_logo.sql`.
- **Never `git commit`.** The owner commits. Each task ends with a suggested commit message.
- **Branch:** `feature/firm-logo`, created from `origin/main`.
- **Quality bar:** `pnpm test`, `pnpm typecheck` and `pnpm lint` clean at the end of every task.

## Review Focus
1. **A file declared PNG that is actually something else** (JPEG bytes, a PDF, or text renamed `.png`). It must be refused, its object deleted, and the firm's logo left unchanged. Task 2 tests this.
2. **The public route asked for another firm's logo, a key outside `branding/`, or an encoded traversal** (`..%2F`). It must answer 404 and never stream anything else. Task 2 tests this.
3. **An upload started but never completed** (tab closed). The firm's logo is unchanged and nothing breaks. The stray object is harmless. Task 2 tests this.
4. **Replacing a logo.** The previous URL still serves the old image, so emails already sent keep their logo. Task 2 tests this.
5. **Document storage not configured** (no `S3_BUCKET`). Starting an upload gives the existing 503 `NOT_CONFIGURED`, and emails and pages for firms with no logo render exactly as before. Tasks 2 and 3 test this.

  - `DocumentStorage.readObject(key: string, maxBytes: number): Promise<Buffer | null>`. Returns null when there's no object. It reads at most `maxBytes + 1` bytes, using a `Range` header in S3, so the caller can detect oversize.
  - `FakeDocumentStorage`: `data: Map<string, Buffer>`; `putDirect(key: string, body: Buffer): void`, which stands in for the browser PUT; `signPutUrl` returns `https://fake-storage/put/<key>`. `objectSize` and `remove` also cover `data` entries.

    - `MAX_LOGO_BYTES = 1_048_576`
    - `logoPath(orgId: string, logoId: string, type: LogoType): string`, which returns `/api/v1/public/logos/${orgId}/${logoId}.${type}`
  - `OrganizationDto.logoUrl: string | null` and `MeResponse.organization.logoUrl: string | null`. Both are the relative `logoPath(...)`, or null.
- **Migration:** `ALTER TABLE organizations ADD COLUMN logo_id UUID, ADD COLUMN logo_type VARCHAR(3) CHECK (logo_type IN ('png','jpg'))`, plus `CHECK ((logo_id IS NULL) = (logo_type IS NULL))`. Add a header comment pointing at the spec and saying old logo files are kept on purpose.

- Test: `apps/api/test/organization-logo.test.ts`

**Interfaces:**
- Consumes: Task 1's storage methods, `LOGO_TYPES`, `MAX_LOGO_BYTES` and `logoPath`; `recordAudit`; `getOrganization`.
- Produces:
  - **Start:** `POST /api/v1/organization/logo/uploads` → 201 `{ data: { logoId: string; uploadUrl: string; expiresInSeconds: 300 } }`, with `Cache-Control: no-store`.
  - **Complete:** `POST /api/v1/organization/logo/:logoId/complete` → 200 `{ data: OrganizationDto }` with the new `logoUrl`. On a bad file it returns 422 `VALIDATION_ERROR` with the spec's copy, and the object is removed.
  - **Remove:** `DELETE /api/v1/organization/logo` → 200 `{ data: OrganizationDto }` with `logoUrl: null`. It's a no-op 200 when there's no logo.
  - All three use `requirePermission('organization.manage')`.
  - **Public route:** `GET /api/v1/public/logos/:orgId/:file`.
    - Validate `orgId` as a UUID and `file` against `/^([0-9a-f-]{36})\.(png|jpg)$/`; anything else is 404.
    - Read the key with `readObject(key, MAX_LOGO_BYTES)`; null is 404.
    - Respond with the bytes and the global-constraint headers, with `Content-Type` from the extension.
    - No session needed.
  - `logo.service.ts`:
    - `startLogoUpload(deps, ctx, input)`
    - `completeLogoUpload(deps, ctx, logoId, input, meta)`. Reads with `readObject`. Refuses when the object is missing, longer than `MAX_LOGO_BYTES`, or when its magic bytes don't match `contentType`. Then sets `logo_id`/`logo_type` and audits `organization.logo_updated`.
    - `removeLogo(deps, ctx, meta)`. Clears the columns and audits `organization.logo_removed`. Deletes no files.
